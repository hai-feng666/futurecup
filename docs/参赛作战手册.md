## 2. 先看它跑起来（10 分钟）

### 2.1 命令行跑一次

```powershell
python -m harness.cli run
```

你会看到：6 个节点依次执行，每次调度都打印"为什么选这个 Agent"，
以及验证记录（`recompute` 一行会显示匹配/缺失/幻觉数字），最后输出诊断报告。

### 2.2 演示"验证抓错 → 自动返修"

```powershell
python -m harness.cli run --fault
```

**关键观察**：`analyze` 节点会出现第 2 轮，
验证记录里出现 `★` 标记和 `幻觉数字=[...]`——这就是 Self-Loop 的证据，也是录制视频的核心镜头。

### 2.3 打开可视化控制台

```powershell
python -m harness.console
```

浏览器打开 **http://127.0.0.1:8080**。
- 左侧：运行历史
- 中间：DAG 图（灰色=未跑，绿色=通过，**黄色=返修过**）
- 表格：每个节点的调度决策与验证证据
- 底部：最终报告

点右上角「⚡ 强制故障运行」——黄色节点会出现在图上，这一屏就是视频里最好看的一帧。

> 也可以双击 `start_console.bat`。

1. 打开 https://platform.deepseek.com/ ，注册 + 实名认证
2. 充值 **10 元**（跑完全部实验绰绰有余）
3. 「API keys」→ 创建，复制 `sk-` 开头的字符串（**只显示一次，立刻粘贴到记事本**）

### 3.2 配置环境变量

```powershell
cd "D:\deepseek\one\futurecup"
$env:HARNESS_BACKEND  = "openai"
$env:HARNESS_BASE_URL = "https://api.deepseek.com"
$env:HARNESS_API_KEY  = "sk-你的key"
$env:HARNESS_MODEL_FAST   = "deepseek-chat"
$env:HARNESS_MODEL_STRONG = "deepseek-chat"
```

注意：这样设置**只对当前这个 PowerShell 窗口有效**，关掉就没了。
想省事就复制 `.env.example` 为 `.env` 填好，每次开窗口时重新 `$env:` 一遍即可
（本项目不自动读 .env，避免多一个依赖）。

### 3.3 验证

```powershell
python -m harness.cli run
```

**判断标准**：输出里 `backend=` 显示 `openai`，且节点耗时从 `20ms` 变成 `1000ms+`，说明真的调用了模型。

### 3.4 如果失败（按顺序排查）

| 现象 | 原因 | 处理 |
|---|---|---|
| `HTTP 401` | key 错了或没生效 | 重新复制 key，确认没有空格 |
| `HTTP 402` | 余额不足 | 充值 |
| `请求失败: <urlopen error>` | 网络/代理 | 换网络或开代理，再试 |
| 无报错但内容奇怪 | 模型输出格式不合验证器 | 正常，正是要调提示词的地方（见第 5 步） |
| 卡住超过 20 分钟 | — | **停止，切回 mock 继续做后面的事**，明天再回来 |

> 铁律：真模型只是"加分项"，mock 模式已经能完整演示。**不要为了接模型耗掉一整天。**

## 5. 提示词怎么调（D2–D3 的核心工作）

打开 `config/agents.json`，每个 Agent 有 `system` 字段。三个原则：

1. **角色要具体**：不要"你是分析师"，要"你是经营分析师，所有数字必须来自工具返回的事实表"。
2. **输出格式要硬性规定**：要求"每条结论后用方括号标注事实编号 F1–F9"，
   否则验证器抓不到锚点，`recompute` 会一直判失败。
3. **把验证规则写进提示词**：例如"绝对值大于 1000 的数字必须能在事实表中找到，
   否则不要输出"——**让 Agent 提前知道它会被怎么检查**，通过率会明显上升。

调试技巧：先用 DeepSeek 网页版（platform.deepseek.com/playground）粘贴
`system` + 一段真实输入，看输出格式对不对，调好了再粘回代码。这样不烧钱。
